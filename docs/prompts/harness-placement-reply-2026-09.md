### Platform facts, verified against docs.github.com today

- Scheduled workflows are disabled after sixty days without activity **in public repositories
  only**. 26's doctor check on the schedule matters for the public beds and is moot on private
  ones.
- Code scanning on a private repository needs a GitHub Code Security licence. 26's fallback to
  check-run annotations and one comment is the right default, and it should be the default on
  private repositories rather than a 403 path.
- Push rulesets, the only mechanism that restricts pushes by file path, are documented for
  private and internal repositories. On the public beds (tilth, umbel, copeca, pollen) the
  guardrail paths are held by CODEOWNERS, the required check and a branch ruleset, and 26 should
  say so instead of promising a push ruleset everywhere.
- GitHub's hardening guide: self-hosted runners "should almost never be used for public
  repositories", because anyone who can open a pull request can compromise the runner and reach
  its secrets and token. This changes the clock's design in 26 and 29. The owner's machine must
  not be registered as a runner on any public bed, label or no label. Put the builder jobs in one
  private repository, the proof repository or a private clock repository, that checks out the
  public beds and runs `tend2 next` and the harness loop against them. Public beds keep hosted
  runners and the deterministic check only.
