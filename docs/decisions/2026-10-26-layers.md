# The garden's layers, and who owns each

2026-10-26. The owner's decision, worked out with the umbrella agent over one session. It
replaces the shape in `docs/building-the-garden.md` §0 (four rows, eight beds) and the bed count
in `docs/plotplot-architecture-review-2026-09.md` §4. Where this page and an older page differ,
this page holds.

## What plotplot is now

plotplot is a software factory built as separate tools. Each tool owns one responsibility,
does it well, works alone, and works better beside the others. The factory finds what to build,
builds it, ships it, markets it and learns from it, with a person deciding direction and saying
yes where it matters. The garden's invariants (law §1) all still hold: agents produce and code
decides, files are the substrate, every tool works on every agent CLI, every tool has full value
alone.

The tools stay open, as the direction memo says (`docs/garden-direction-2026-09.md` §2). What
changes is what they are for: together they are a factory, and the products it makes may earn.

## The layers

Building a product passes through these layers, roughly in this order. Each layer has exactly
one owner. A bed may read any layer and writes only its own. A bed that wants a change in another
layer proposes it, and the owner applies it.

| Layer | Owner | Built today |
|---|---|---|
| Finding what to grow: needs nobody serves well, scored as seeds | glean | no |
| Sources → raw signal: what people say, verbatim, dated, sourced | mull | as a model-driven extractor; to be redefined |
| Personas → jobs → outcomes | cultivate | as a package with measured tests; not yet a bed |
| Capabilities → features → screens → flows | graft | `read` only |
| Brand → mockups → screen designs → components | petals | brand only |
| Architecture → structure → data model → APIs | trellis | no |
| Plan and verify | tend2 | yes |
| Build | pleach, umbel, mycelium | yes |
| Ship: deploy, domains, email, billing, monitoring, rollback | transplant | no |
| Marketing: positioning → messaging → channels → campaigns | pollen | no (the name passes from the messaging tool) |
| Release → tell → measure → learn | harvest | no |

Harvest's learning returns to cultivate's outcomes and to glean's scoring, which closes the loop.

| Hand tools | tilth | reads code | yes |

| | well | the one door for every call that costs money or needs a key | no |

| | upkeep (working name) | keeps shipped products from rotting | no |
| | the stem | plants the tools into each agent CLI and checks they fit; gains `status` | yes, without `status` |

Outside the factory: the **compass**, a short file the owner writes saying what the portfolio is
for, whom it serves, what is never built and what a bet may cost; the **seedbank**, where seeds
wait; and the company's own books, kept by the owner's business skill, which reads revenue from
harvest and costs from well.

copeca leaves the garden. It stays a public benchmark for people who build agent tools. The
number it is named for, cost per correct average, becomes a report pleach reads from its own
receipts joined with well's ledger (pleach issue 172). The one controlled experiment the garden's
claim needs, whether the second-opinion audit pays for itself, runs once as pleach issue 173.

## Rules that hold the structure together

1. **One owner per layer.** No layer is shared, and no bed owns two.
2. **One map format.** Every layer's own content is stored as pages in tend2's format, with a
   page kind per layer. tend2 owns the format and its export (`tend2 export --json`); each bed
   owns the content of its kinds. Content that already has a standard format keeps it, and a
   page points at it: raw items as JSON Lines, schemas as JSON Schema or SQL, API specs as
   OpenAPI, dates as iCalendar, findings as SARIF, mockups as image files.
3. **Agents produce, code decides.** Each layer's content is drafted by an agent through that
   bed's skills and approved by a person. Each bed's tool checks it with code, or with a typed
   judge in a shape code can refuse.
4. **Every tool works alone** with nothing else installed, through files any person could write
   by hand, and composes through contracts, never imports.
5. **Time stays outside the tools** (law §6). The gardener and every cadence command are
   idempotent commands; what wakes them is the operating system's scheduler or a workflow file
   in the repository.
6. **Nothing is a proxy or a server** (law §6, invariant 2). well wraps a call as a command and
   a library; gate is files plus delivery adapters at the edge.
7. **Every metered call goes through well.** It reserves the estimated cost before sending,
   shares the reservation with every spender of the same budget, records what was charged, and
   never resends a call that may already have been charged.
8. **Every outbound act waits for a yes where the compass says so.** hedge refuses the act until
   gate holds a yes bound to that exact request.

## What this overturns

- Law §0, the shape table: replaced by the two tables above.
- Law §5, "mull is not a bed": mull returns as a deterministic fetcher with no model in it.
- Law §5, weeder "guard replaces hedge": weeder keeps its guard at commit and push through git
  hooks; hedge owns the boundary before a tool call runs. Two moments, two owners.
- Law §6a, the tend2 and copeca boundary: moot once copeca leaves.
- The review's eight beds (§4): replaced by this page. The review's cut of doc truth to a skill
  plus one weeder rule: stake is a bed.
- The direction memo's "not the income plan": it still holds for the tools; the products the
  factory makes may earn.

The law's sections are rewritten to match when each bed is planted, in the planting pull request.

## Moves in beds that exist

- **tend2** adds a page kind per layer (job, outcome, capability, feature, screen, flow,
  component, rule, seed) and keeps its existing kinds; its persona, shape and wireframe skills
  move to the beds that own those layers.
- **graft** owns features: capability and feature pages, then screens and flows. It reads
  people through cultivate's pages instead of its own issue reader.
- **cultivate** becomes a bed with its own map and `garden.json`. It reads raw items in mull's
  format, which a person can also write by hand, so it keeps full value alone.
- **mull** becomes a fetcher: the same sources at the same time give the same bytes, append-only,
  a census per channel that warns when one goes quiet. cultivate's source adapters move into it.
- **petals** grows from brand to design system: a mockup skill, screen designs, components, and
  a check that the built screen matches its design.
- **pleach** adds the cost-per-correct report from receipts and well's ledger.
- **the stem** adds `plotplot status`: what is running, what failed, what waits for the owner.

## Order

Each new tool gets a draft under `docs/ideas/`, with its kill criterion, before any build. The
order follows what blocks the most:

1. The rename of pollen to mycelium, so the names are settled.
2. tend2's page kinds, because every layer waits on them.
3. well, before graft builds its own judge client and before anything spends money.
4. hedge and gate, before anything publishes, deploys or spends without the owner.
5. The gardener and almanac, so work moves without a chat session open.
6. glean with the compass, first as a rough check on the owner's own projects.
7. Product one through every layer, recording each place a person had to step in. That list
   decides the order of trellis, transplant, pollen, harvest, upkeep and stake.
